# 락은 걷는 것이 아니다 — uncross 수리와 그것이 뒤집은 아침 숫자 셋 (2026-09-15 밤)

[OWNER 2026-09-15] 「양면을 다 세운다」 판정. §11 의 불변식 하나를 바꾼다.

**바뀐 것**: `uncross` 는 이제 **간격이 «있는» 크로스만 걷는다.** 간격 0(락)은 양면을 다 세운다.
불변식이 «오퍼 금리 < 비드 금리» 에서 **«오퍼 금리 <= 비드 금리»** 로 바뀌었다.

---

## 1. 왜 — 화면이 체결의 4분의 1에서 틀린 쪽을 가리키고 있었다

| 실측 (국고 귀속 체결 38,746건) | |
|---|---:|
| uncross 가 **걷어낸** 호가에서 난 체결 | **23.5%** |
| 그중 그 레벨이 화면에서 통째로 사라진 것 | 0.2%뿐 |
| → 나머지는 **그 레벨에 반대편만 남아 있었다** = 락 | 거의 전부 |
| 걷어낸 호가의 나이 중앙 | 26초 (남은 쪽 11초) |

화면은 「3.710 사자」를 보여 주는데 실제로 일어난 일은 「3.710 팔자가 맞았다」였다.
스테일해서 지운 것도 아니다.

**규칙의 근거가 이 시장에 없었다.** uncross 는 v2.5 에서 코인베이스 책의 «크로스 0» 불변식을
옮겨 온 것인데, 그건 **체결 엔진이 강제하는** 성질이다. 메신저 시장에는 그 엔진이 없어서
**락이 진짜 상태로 오래 선다**(v8 실측 하루 907건 = 국고 호가의 40%).
오너의 「락은 이벤트가 아니다」(09-03)는 이벤트 피드 이야기였지 사다리 표시가 아니었다.

## 2. ★그런데 그 규칙이 «측정» 까지 오염시키고 있었다

오늘 아침 `RESULT_book_dynamics_2026-09-15.md` 의 수를 같은 스크립트로 다시 냈다.
표본·규약 전부 같고 **uncross 한 줄만 다르다.**

| | 락 걷던 때(아침) | 락 세우는 지금 |
|---|---:|---:|
| uncross 가 걷어낸 호가에서 난 체결 | 23.5% | **0.7%** |
| 체결 시점 호가 스프레드 **0(락)** | 0.3% | **84.2%** |
| 체결 시점 호가 스프레드 0.5bp | 93.6% | 14.2% |
| 유효 반스프레드 중앙 | 0.25bp | **0.00bp** |
| 유효가 음수(mid 안쪽) | 19.7% | **0.5%** |
| 최우선 «레벨» 체결률 | 81.2% | **84.3%** |
| 불균형→공격 AUC (그룹내) | 0.578 (0.594) | 0.571 (**0.620**) · 위약 0.511→**0.501** |
| 불균형→15분 뒤 mid 그룹내 ρ | **+0.188** | **−0.038** (부호가 뒤집혔다) |
| 딜러 품질 상/하 «체결/호가» | 0.0191 / 0.0119 = **1.60배** | 0.0174 / 0.0133 = **1.31배** |
| 품질 회귀 계수 | 0.155 (±0.011) | **0.044 (±0.005)** |

### 뒤집힌 것 셋 — 아침 문서에서 고쳐 읽을 것

**① 「책은 한 틱이다」는 절반이 우리 인공물이었다.** 체결 시점 스프레드가 0.5bp 93.6% 라고
적었는데, 그건 **락에서 한 쪽을 지운 뒤의 간격**이라 구성상 한 격자다. 락을 세우면
**체결의 84.2%가 «락 상태»** 에서 난다 — 거래가 날 때 두 면은 **같은 레벨에 있다.**
호가 격자가 0.5bp 인 것은 그대로지만, **거래가 나는 순간의 폭은 0 이다.**
(그래서 «체결 알파 없음» 결론은 약해지지 않고 오히려 강해진다. 먹을 스프레드가 아예 없다.)

**② 「불균형 → 15분 뒤 mid」의 부호가 뒤집혔다.** 아침에 그룹내 +0.188 을 «호가 mid 의
되돌림» 으로 설명했는데, **그 되돌림 자체가 우리가 만든 것**이었다. 락에서 한 쪽을 지우면
mid 가 반 틱 움직이고 그 방향은 늘 «사람이 많은 쪽의 반대» 다. 락을 세우니 −0.038(위약
−0.001)로 내려앉고 **부호가 R2 와 같은 쪽**이 된다:

| 직전 불균형 | 금리↓ | 금리↑ |
|---|---:|---:|
| 오퍼 우세 | 20.1% | **30.7%** |
| 비드 우세 | **36.0%** | 19.5% |

비드가 두터우면 금리가 내려간다. 경제적으로 말이 되는 방향이고, 크기는 여전히 작다.

**③ Hendershott 재현이 1.60배에서 1.31배로 약해졌다.** 락을 세우면 «게시 순간 최우선 이상»
이 더 쉬워져(반대편과 같은 레벨도 최우선이다) 품질 축이 무뎌진다. **효과는 살아 있다**
(위약은 0.015 로 평평하고 상 0.0174 · 하 0.0133) 지만 **아침에 적은 크기는 과장이었다.**

**④ 안 뒤집힌 것**: 불균형 → 공격 방향은 그대로 산다(AUC 0.571, 그룹내 0.620, 위약 0.501).
구간별도 같다(오퍼 우세 → 사 감 39.8% · 비드 우세 62.9%).

> **교훈: 표시 규칙이 측정을 오염시킬 수 있다.** uncross 는 «화면을 어떻게 그릴까» 로 들어온
> 규칙인데, 같은 함수를 연구도 쓰고 있었다. 한 줄이 헤드라인 넷 중 셋을 움직였다.

## 3. 무엇이 또 좋아졌나 — 우리가 만들던 가짜 이벤트

09-03 재생에서 **이벤트 598 → 537**. 줄어든 61건은 전부 «최우선 갱신» 이다(60 → 39).
락에서 한 쪽을 지우면 그 면의 최우선이 다음 레벨로 **뛰어서** 「최우선이 바뀌었다」 이벤트가
났다. **우리가 지우고 우리가 놀랐던 것**이다. 같은 재생에서 최우선 체결률 82.5% → **87.5%**,
유효 반스프레드 중앙 0.25 → **0.00bp**.

`verify [C]` 는 이제 **«오퍼 <= 비드 · 간격 있는 크로스 없음»** 을 보고 **락 종목 수를 따로 센다**

### 화면 — 락을 락이라고 말한다

- **한 행에 양면**(`ObLevel` 이 `S`·`B` 를 다 갖는 칸). ★이걸 안 하면 **잔량 합에는 들어가는데
  행이 없어** 「매수 합 870억인데 보이는 건 750억」이 된다(실측 26-7). 두 화면 다 고쳤다.
- 스프레드 줄이 **「락 3.790 · 같은 레벨에 양면」**, 요약 칸이 **「락 / 양면」**.
- 칸에 `락` 배지, 행에 옅은 바탕. **락 칸에는 바램을 안 먹인다** — 거래가 나는 자리다.
- `View.ob.best.lock` 신설(스키마 → `openapi.json` → `api-types.d.ts`).

**실측 한 건**(20260903 15:30, 26-7): 고치기 전 화면은 «오퍼 3.790 / 비드 3.795 / 스프레드
0.5bp» 였고 그날 체결은 **3.790** 이었다. 고친 뒤 화면은 «락 3.790 · 양면(400억 4건 대
120억 2건)» 이다. 숨어 있던 비드 둘이 바로 체결이 난 자리였다.

## 6. 한계

1. 락을 «세운다» 는 것이 «양쪽 다 firm 이다» 라는 뜻은 아니다. 둘 중 하나는 스테일일 수 있다.
   우리는 그걸 가릴 방법이 없다 — 그래서 TTL 과 나이 바램이 남는다.
2. 간격 «있는» 크로스는 여전히 걷는다(0.7%). 그 판정은 안 건드렸다.
3. 유효 스프레드는 이제 84%에서 구성상 0 이다. **더 이상 정보가 없는 지표**라 화면에 남기되
   읽는 법을 알아야 한다(동향 탭의 «유효 반스프레드 · 호가» 칸).
4. 아침 문서의 수치는 **여기 표로 대체된다.** 원문은 기록으로 남겨 둔다.
