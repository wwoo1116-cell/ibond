# 알람 사이징·교정 — 「1등 알람」을 재 보니 방아쇠를 바꿔야 했다 (2026-09-30)

재현: `python alarm_sizing.py --calibrate` · `python alarm_sizing.py --watch 2300 out.jsonl`
설계·판정: `PROMPT_next_2026-09-30-alarm.md`

[OWNER] 「1등은 호가 올라오면 알람 띄워주는 식으로」로 시작했다. **읽기만 해서** 산
백엔드(`:8301`)를 재고, 그 결과가 방아쇠를 바꿨다. 이 문서는 수만 적는다.

## 0. 구조 — 먼저 알아야 할 것 넷

| | 실측 |
|---|---|
| 도는 것 | `uvicorn kbond_api:app` **:8301** — 문서 예시의 8302 가 아니다. `:3400` 은 `python -m http.server`(구운 화면) |
| 순위 | `/api/view?lane=cr` 가 **이미** `pr`·`pn`·`pk`·`padj` 를 싣는다(336KB · 순위 실린 오퍼 중앙 192 · 1등 중앙 23) |
| 무리 중앙 | 같은 페이로드의 `buckets` 26칸이 `bp_med`·`bpc_med`·`n`·`est`·`ttm_lo/hi` 를 준다 |
| 전달 | `/events` SSE 이미 있다. 가리기는 **책에 넣을 때** 걸려 `/book.json`·`/feed.json`·SSE 어디에도 실명이 없다(지금 `masked:false`·`masked_tel:true`) |

**즉 알람에 새 계산이 필요 없다.** 필요한 것은 판정과 배너다.

## 1. ★크레딧에는 `best`·`cross`·`first` 이벤트가 **없다** — 한 줄 때문에

```python
# kbond_live.py::_after_quote
if lane not in ("ktb", "msb") or e.get("y") is None:
    return          # ← 크레딧은 여기서 돌아간다
```

실측: 스냅샷의 이벤트 240건 중 `best` **63건이 전부 국고(61)·통안(2)**, 크레딧 **0**.

가설 둘을 세웠고 **둘 다 틀렸다**:
- 「크레딧은 `y` 가 없어서」 → 아니다. `y` 있는 비율 **842/850 = 99.1%**.
- 「크레딧은 종목당 호가가 하나라서 직전 최우선이 없어서」 → 아니다. 종목당 오퍼가
  **단독인 비율이 크레딧 25.4%(181종목) · 국고 65.1%(109종목)** 로, 크레딧이 **더 낮다**.

원인은 위 한 줄의 명시적 게이트다.

## 2. 1등 교체 실측 — 43%가 거짓이다

20초 폴 × **115회** · 14:52~15:30(**38.1분**, 도착이 가장 많은 창) · 오류 0.

```
책 판 바뀜        1,280번 (0.56/초)
순위 실린 오퍼     중앙 192  ·  1등 수 중앙 23
1등 교체(레벨 제외)   7건 → 11.0건/시
같은 딜러 재마크      2건   ← 원시 9건 중 2건. 동일성에서 레벨을 빼야 하는 근거
새 무리 등장       116건 → 183건/시   ★방아쇠로 쓸 수 없다(PEER_MIN 넘나드는 인공물)
교체 7건 전부 «좁은 무리»

★**교체 7건을 «도착»과 «TTL 만료»로 가르면 4 대 3 이다.** 새 1등이 직전보다 덜 싸면
아무것도 안 온 것이다 — 직전 1등이 늙어 죽고 더 나쁜 것이 왕관을 물려받았다:

```
회사채 AA0 1~2   −2.0 → −5.0   만료 (3bp 나빠졌는데 「1등이 바뀌었다」)
캐피탈 AA− 2~3   −4.0 → −4.5   만료

**43%(3/7)가 «책이 나빠진» 알람이다.** 문턱 돌파 방식은 이 오류가 구조적으로 불가능하다.

## 3. 문턱 교정 — 무리 중앙 대비

계열·등급마다 정상 민평대비가 달라 전역 bp 하나로는 한쪽에서만 울린다. `bp_med`·
`bpc_med` 가 이미 오므로 **무리 중앙 대비**로 걸면 정규화가 공짜다.
재는 자는 하나여야 한다 — 무리가 `bpc_med` 를 가졌으면 `bpc`, 아니면 `bpe`
(`peer_rank` 의 「섞어서 재지 않는다」와 같은 규칙).

**스냅샷 둘, 25분 차:**

|---|---|---|
| p25 / p50 / p75 | −0.94 / 0.00 / +1.06 | −0.50 / 0.00 / +0.98 |
| p90 / p95 / p99 | +3.19 / +4.50 / +9.69 | +2.52 / +3.75 / +15.75 |
| +1bp | 25.5% → **9.7건/일** | 22.6% → **8.6건/일** |
| +2bp | 15.5% → 5.9 | 11.3% → 4.3 |
| **+3bp** | 11.8% → **4.5** | 6.0% → **2.3** |

⚠**하루 환산의 분모**는 원장 역사에서 잰 도착 수다 — 이름+민평+값+오퍼를 하루로 접어
**중앙 38건**(2024-02~2026-09 · 541영업일 · p25 14 · p75 70 · p90 103 · 최대 195).

★★**한 스냅샷으로 문턱을 정하면 안 된다.** 25분 차이로 +3bp 가 4.5건과 2.3건 사이를
움직였다. 며칠 여러 시각에 `--calibrate` 를 돌려 정할 일이다. 지금 근거로 말할 수 있는
것은 **+2~3bp 가 하루 2~6건**이라는 자릿수뿐이다.

## 4. 기존 레인이 이미 잰 것 — 알람이 물려받을 수

- **1분 벼랑** — 최우선 호가 나이별로 «그 레벨에서 체결이 난» 비율(국고 전 이력 35,654건):
  **~1분 90.6%**(n=27,973) · 1~5분 **61.2%** · 5~15분 29.6% · 15~30분 16.7%.
  → 알람의 유효기간이 1분이다. `AGE_STEPS = (60, 300)` 이 이미 그 눈금이다.
- **재게시가 레벨을 1bp 이상 움직일 확률**(21영업일 국고 44,515쌍): 0-5분 0.7% ·
  5-15분 5.1% · 15-30분 14.1% · 30-60분 25.9% · 1-2h 41.8% · 2h+ 54.2%
- `CROSS_MIN_BP = 0.5` — 「같은 레벨(락)은 이벤트가 아니다」
- TTL 하드컷 국고·통안 30분 · 크레딧 120분

## 6. 함정 — 이 측정에서 내 판단이 세 번 뒤집혔다

1. 「라이브 레인은 순위를 계산하지 않는다」 → **틀림.** 도는 것은 `kbond_api` 이고
   `peer_rank` 를 이미 낸다(:8301 에 있어서 옛 `kbond_live.py` 로 오인했다).
2. 「방아쇠가 이미 있다(`best`)」 → **크레딧엔 없다**(§1 의 한 줄).
3. 「크레딧은 종목당 호가가 하나라서」 → **틀림**(단독 25.4% 대 국고 65.1%).

그리고 하나 더 — **`pk` 는 표시 라벨이고 무리 키가 아니다.** 넓은 무리 fallback 이
라벨에서 등급을 빼기 때문에, `pk` 로 묶으면 「1위가 없는 무리」가 생긴다(실측 26 중 6).
예: 「무위험 1~2 · 실린 1 · pn 7」. 무리 키는 `(pk, pn)` 쌍이나 실제 무리 산출로 잡는다.
