# 두 화면 지문 대조 — React 전환 3단계 · 2026-09-11

## 0. 한 줄

「나란히 하루 띄워 놓고 눈으로 본다」를 **기계가 세도록** 바꿨다(`compare_screens.mjs`).
첫 실행에서 **네 자리가 어긋났고**, 넷 다 «옛 화면이 틀린 쪽» 이었다. 고친 뒤
**다섯 영역 88줄 전부 0건 차이**다.

## 1. 어떻게 쟀나

동결 리플레이 백엔드 하나(`KBOND_REPLAY=20260903 KBOND_AT=15:30:00`, :8302)에 두 화면을
붙였다. **같은 책이어야 대조가 뜻을 가진다.** 재는 것은 API 응답이 아니라 **화면에
그려진 글자**다 — 사람이 읽는 것이 그것이라서다.

```
node compare_screens.mjs            # 헤드리스 크롬(CDP)이 두 화면을 열고 칸을 긁는다
```

| 영역 | 줄 수 | 결과 |
|---|---|---|
| 탭 숫자 | 6 | 0건 차이 |
| 히트맵(8행 × 6칸) | 8 | 0건 차이 |
| 크레딧 분류 줄 | 31 | 0건 차이 |
| 크레딧 오퍼 표 | 15 | 0건 차이 |
| 국고 종목 줄 | 15 | 0건 차이 |

## 2. 대조가 잡은 것 넷 — 전부 옛 화면이 틀렸다

### A. 크레딧 버킷의 민평대비 중앙값이 31칸 전부 0.0bp 였다

[OWNER 2026-09-07] 「«민평에 팔자» 를 0bp 로 받으면 버킷의 절반~8할이 0 이 되어
중앙값이 통째로 0 으로 눌린다」 — 그날 **서버(`kbond_view.cr_buckets`)만 고쳤고 옛
화면의 `crBuckets` 는 안 고쳤다.** 그래서 옛 화면을 보던 눈에는 크레딧 분류 줄의
민평대비가 **거의 다 0.0bp** 로 보이고 있었다.

```
무위험 AAA   옛 0.0bp   새 -1.0bp     (52건 중 30건이 «민평에»)
무위험 AA+   옛 0.0bp   새 +1.4bp
특은채 AAA   옛 0.0bp   새 -1.0bp
```

고쳤다 — 옛 화면도 `atmp` 를 중앙값에서 빼고 따로 센다(툴팁에 「N건 중 M건이 민평에」).

### B. 오퍼 표가 «민평에» 를 +0.0bp 로 적고 있었다

같은 09-07 판정의 다른 반쪽이다. 새 화면은 «민평» 이라고 쓰는데 옛 화면은 `0.0` 이었다.
딜러가 정확히 0 을 부른 것처럼 보인다. 고쳤다.

### C. 새 화면의 종목 목록에 구획이 없었다

[OWNER 2026-09-03] 「지표물이 뭔지 안 보인다」로 옛 화면에는 **지표물·차기지표물 /
오늘 활동 / 어제(활동 순)** 세 구획이 있는데, 새 화면은 통째로 만기순이었다. 15줄이
전부 어긋나며 드러났다. 새 화면에 구획을 옮겼다.

### D. 새 화면이 «어제 마지막 수준» 을 안 보여 줬다

오늘 호가가 없는 줄에 옛 화면은 어제 종가를 흐리게 적는데 새 화면은 «—» 였다.
지표물은 오늘 값이 없는 날이 흔해서 **커브의 기준이 빈칸으로 보인다.** 폴백
(`pv.mid → pv.fill → pv.a/b`)과 «어제 체결» 배지·«어제 N건» 을 옮겼다.

곁가지로 **수요 매칭 건수**가 새 화면에 없어서 함께 옮겼다(옛 화면 부제에 있던 값).

## 3. 도구가 스스로 틀렸던 것 셋 (기록해 둔다)

대조기를 처음 돌렸을 때 «차이» 로 보였다가 도구 잘못으로 밝혀진 것들이다. 같은 함정을
다음에 또 밟지 않도록 주석으로 박아 뒀다.

1. **캐시** — 크롬이 옛 `index.html` 을 꺼내 써서 «고친 화면» 대신 «어제 화면» 을
   대조했다(out 은 `page-78b2…` 를 가리키는데 페이지는 `page-c7ac…` 를 들고 있었다).
   → `Network.setCacheDisabled`.
2. **선택자** — 새 화면의 `.kb-li` 는 «관심»(axes) 목록에도 붙는다. 종목 줄은 `.kb-li2` 다.
3. **칸 차례** — 새 화면은 [이름·값·부제·민평대비], 옛 화면은 [이름·부제][값·민평대비] 다.
   마지막 칸을 집으면 «나이 칩» 을 값으로 읽는다.

## 4. 전환 판정에 쓸 말

- **수는 이제 같다.** 다섯 영역 88줄에서 0건 차이다.
- **틀렸던 쪽은 옛 화면이었다.** 넷 중 둘(A·B)은 09-07 오너 판정이 서버에만 반영돼
  있던 것이고, 둘(C·D)은 새 화면이 못 옮긴 것이었다. 지금은 양쪽 다 같은 규칙이다.
- 남은 것은 «같은 수를 다르게 배치한 것» 뿐이다 — 그건 취향이고, 오너가 볼 자리다.

⚠이 대조는 **동결 리플레이 하루(20260903 15:30)** 로 잰 것이다. 장중 실황에서는 두
화면이 각자 다른 순간을 그릴 수 있어(폴링 주기가 다르다) 0건이 나오지 않는다 —
그건 어긋남이 아니라 시차다. 판정은 동결로만 한다.
