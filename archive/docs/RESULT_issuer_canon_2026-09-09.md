## 2. 다섯 자리에서 갈라졌다

1. **사전에 없었다.** `kbond_live._ALIAS_OFFICIAL` 에 산금 항목이 0개. 한전·농중·
   삼카는 있는데 산금만 빠졌다.
2. **머리말 채취기가 접미를 함께 물었다.** `RE_ISSUER` 는 붙어 있는 한글을 끝까지
   문다. `_ISSUER_STOP` 은 **낱말 전체가 같을 때만** 버려서 「산금팔자」를 못 막았다
   — 09-07 에 고친 「만기」와 같은 병이다.
3. **회차 제거기가 숫자 회차만 알았다.** `RE_TAIL_SERIES` = `\d{1,4}-\d{1,3}$`.
   산금 회차는 문자코드(D18·GC78·KR310218)라 하나도 안 떨어졌다.
4. **접는 자리가 둘인데 서로 다른 것을 접었다.** 원장은 `canon_issuer(BondName)`,
   화면은 `canon_label` + prefix 루프 **세 벌**. 그런데 `canon_label` 이
   `if how != "power5": return s` 로 alias 를 버려서, 원장은 산은캐를 산은캐피탈로
   접었는데(5,631행) 화면은 산은캐를 따로 세웠다(7,545행).
5. **원장에 발행체 키가 아예 없었다.** 크레딧 4,260,592행 중 BondName 이 있는 건
   **41.4%**. 나머지 58.6% 는 `IssuerCanon` 이 비어, 발행체가 화면 루프의 임시
   이름으로만 존재했다.

덤으로 잡힌 것 셋: 산은캐 → **특은채**인데 산은캐피탈 → **여전채**(같은 회사가 두
버킷에 삶) · 산업금융채권이 회사채로 떨어짐 · prefix 루프가 최장 일치가 아니라
**「농협중앙회회」 3,595행**을 화면에 띄우고 있었음(`농중` 이 `농중회` 보다 앞).

## 3. ★검정이 무너진 자리 — 이번 레인의 가장 중요한 실측

원래 잣대는 「같은 날·같은 만기의 문면 민평이 1bp 안이면 같은 종목」이었다. 이걸
그대로 크레딧 전체에 걸려다가 **못 쓴다는 걸 재고 알았다.**

하드 음성 11쌍(사람이 아는 «확실히 다른» 발행체)으로 잣대 셋을 대조했다. 양성은
셋 다 100% 통과한다. 갈리는 건 음성이다.

| 칸 | 양성 통과 | 하드 음성 오통과 |
|---|---|---|
| (날짜, 만기) | 100% | **3/11** — 국민은행~신한은행 n=178 0.10bp · 신한~우리은행 n=149 0.10bp · 삼성카드~신한카드 n=35 0.10bp |
| (날짜, 만기, 끝전) | 100% | **3/11** — **산금~중금 n=33 0.00bp**(산업은행과 기업은행이 접힌다) |
| **(날짜, 회차, 만기)** | 100% | **0/11** (9쌍은 같은 칸에 아예 안 만나고, 2쌍은 n=1) |

**AAA 은행채는 같은 커브로 매겨져 만기만으로는 원래 안 갈린다.** 그리고 표본을
키울수록 나빠진다 — n>=40 에서 음성 오통과가 **100%** 였다(큰 n 이 곧 큰 AAA).
끝전을 지문에 넣어도 안 산다.

**가르는 정보는 회차뿐이다.** 대신 대가가 있다: 회차를 안 달고 다니는 은어
(산금·중금·수금·한전·농중·도공·예특)는 이 검정으로 **못 붙인다.** 그건 사람이
판정해야 한다.

## 4. 원장(SQL)도 이름은 갈라져 있다 — 그래서 키가 이름이면 안 된다

`kbond` DB 에 발행체 원장이 있었다(`infomax_bond` 42,392 · `bond_info`/
`kofia_bond_info` 24,417 · `marketvalue` 295,635).

- **이름 열은 원장에서도 갈라진다.** 같은 KR3102* 에 `infomax_bond.issuer` =
  한국산업은행 571 · **KDB산업은행 271**, `bond_info.issuer` = 산업은행 428.
  두 표의 공통 ISIN 20,569건에서 issuer 문자열 일치율 **59.8%**.
- **안 갈라진 것은 «분류»다.** `cclass`(=`bond_info.small`)가 벤더의 정규화된
  발행체 키다: `KB캐피탈 <- {KB캐피탈, 케이비캐피탈, 케이비캐피탈(주)}`,
  `IBK기업은행 <- {IBK기업은행, 중소기업은행}`.
- ★**은어의 출처도 원장이었다.** 벤더 종목명이 데스크 은어를 그대로 쓴다 —
  `산금23신할0100-0904-1` 의 머리말 「산금」 → cclass **KDB산업은행 n=1,239 · 100%**.
  종목명 머리말 8,045종 중 **7,058종(87.7%)이 단일 발행체로만** 간다. 손으로 넣던
  별칭의 대부분이 판정이 아니라 자료였다.
- **못 쓴 앵커**: `marketvalue` 로 ISIN 을 역추적하는 길은 지문이 99.9% 유일한데도
  죽었다 — 3사평균이 **ISIN 158개**(국고 지표 universe)뿐이라 크레딧 수확 0%.
- **주의**: 벤더 분류는 산금을 「은행채」로 넣는다. 오너 6분류의 「특은채」와 달라
  매핑 한 겹이 필요하다(그대로 뒀다 — `_SECTOR_RULES` 가 정본 이름을 보고 매긴다).
- `matrix_금융채` 는 산금채를 **(이표)AAA · (할인)AAA 두 커브**로 매긴다. 상품구조는
  이름에서 떼되 **버리면 안 되는 축**이다.

## 9. 데인 것

1. **`.map()` 의 미매칭은 `None` 이 아니라 `NaN` 이다.** `if c is not None` 이 통째로
   뒤집혀 유도 결과가 0종이 나왔다. `str` dtype 에서는 `.where(..., None)` 으로도
   안 돌아온다 — `astype(object)` 로 내린 뒤 바꿔야 한다.
2. **표본을 키우면 검정이 나아진다는 건 여기서 거짓이다.** n>=40 에서 하드 음성
   오통과가 100% 였다. 큰 n 이 곧 큰 AAA 이기 때문이다.
3. **재파싱 중에 사전을 고치면 안 된다.** 워커가 ProcessPoolExecutor 로 뜨므로
   중간에 새 코드를 집어 원장이 반반 섞인다. 고칠 거면 멈추고 고친 뒤 다시 돌린다.
   (이번에 1차 21분을 그렇게 버렸다.)
4. **병합의 «남길 쪽» 규칙을 길이로 정하면 뒤집힌다.** 한쪽이 다른 쪽의 접두면
   긴 쪽을 남겨야 한다 — 안 그러면 한국항공우주산업이 한국항공우주가 된다.
5. **유도가 자기 산출을 다시 먹으면 안 된다.** `kbond_issuer_derive` 는 앵커를
   master + owner 로만 세운다(파생층 제외). 안 그러면 돌릴 때마다 답이 달라진다.
6. **★층이 서로 반대 방향을 가리킬 수 있다.** 검정은 «같다» 만 말하지 «어느 쪽이
   정본인지» 는 모른다. owner 가 `현대케미칼 -> 에이치디현대케미칼`, mp-test 가
   `에이치디현대케미칼 -> 현대케미칼` 이라 순환이 났다. 놔두면 답이 «어디서
   출발했나» 로 정해진다. 지금은 고리 안에서 **가장 낮은 층의 변을 끊는다**.
   가드를 넣자마자 세 건이 걸렸다(NH투자 · 대구광역시 · 현대케미칼) — 손으로
   찾을 수 있는 종류가 아니다.
7. **★벤더는 지방채를 «발행체» 가 아니라 «채권 프로그램» 으로 나눈다.** 서울도시철도
   채권의 `issuer` 가 «서울특별시» 라서 표제어 「서울특별시」가 「서울도시철도」의
   이형태로 빨려 들어갔다(서울특별시채권 -> 서울도시철도). 그래서 **표제어는 다른
   표제어의 이형태가 못 되게** 막았다. 단 보호는 **cclass 에서 온 표제어만** 받는다 —
   issuer 에서만 온 이름까지 지키면 개명을 못 따라간다(산은캐피탈은 issuer 이고
   cclass 는 KDB캐피탈이라 접혀야 맞다).
8. **`split_name` 은 이름 길이만큼 사전을 두드린다.** 826만행에 그대로 걸면 수천만
   번인데 서로 다른 머리말은 3만종뿐이다. `lru_cache` 를 걸었다(20만회 0.01초).
   대신 꼬리를 dict 가 아니라 **정렬된 튜플**로 돌려준다 — 캐시가 걸린 함수의
   반환값을 하류가 고치면 캐시가 오염된다.
9. **★«수확이 늘었나» 는 비율로 보면 속는다.** 머리를 더 잘 걷자 접힘 비율이
   97.4% -> 96.5% 로 «떨어졌다». 이름을 더 많이 **찾아냈고** 그중 사전에 없는 것이
   늘어서다. 분모가 같이 커진다 — 비율이 아니라 **분자(접힌 행 수)**를 봐야 한다.
   실제로 그 비율 하락 안에 진짜 회귀(괄호 뜯어먹기 29,000행)가 숨어 있었고,
   원인별 상위 목록을 다시 뽑고서야 보였다.
10. **여는 괄호만 뜯는 정규식은 조용히 이름을 죽인다.** `[)]?` 를 선택으로 두면서
   내용에 `{0,n}` 을 주면 «(» 하나만 먹고 «주)에스파워» 를 남긴다. 닫는 괄호를
   선택으로 둘 거면 **내용에 반드시 있어야 할 글자**를 요구해야 한다.
11. **꼬리 문법의 검사 순서가 뜻을 바꾼다.** 홑글자 「사」(사회적채권)를 STRUCTURE 에
   넣자 「사자」가 「사」+「자」로 쪼개져 산금사자가 통째로 안 접혔다. 여러 글자
   토큰(DROP)을 홑글자보다 먼저 봐야 한다.
12. **★가드는 «판정할 자격이 있는 것» 으로만 짜야 한다.** 근접층에 «계열이 같을 것» 을
   가드로 넣었다가 뺐다. 원문 줄임말은 정본이 아니라서 `classify_issuer` 가 무의미한
   답을 낸다. 그 무의미한 답으로 걸러서 옳은 것을 막았다 — 공급망안정화 ->
   한국수출입은행, 예보기금 -> 예금보험공사, 경북지역 -> 경상북도.
13. **★유도가 자기 산출을 먹는 자리는 «앵커» 만이 아니다.** 근접층은 앵커에서 자기
   산출을 걸렀는데도 두 번째 실행이 «남은 게 3종» 이라고 답했다 — «무엇이 아직
   raw 인가» 를 정할 때 지난 산출이 이미 반영돼 있어서다. 굽기 전에 산출을
   지우고 사전을 **다시 읽어야** 한다.
14. **★검정이 과접기를 잡아 줬다.** 근접층이 한화토탈에너지서비스를 한화토탈에너지스로
   접었고 `test_issuer` 의 KEEP_DISTINCT 가 그걸 FAIL 로 세웠다. 이름 모양으로 접는
   층을 만들 거면 **접으면 안 되는 쌍의 목록을 먼저** 갖고 있어야 한다.
15. **★정규식 매치 구간을 «본문» 으로 쓰면 안 된다.** 양면 분할에서 `RE_SIDE` 의 매치를
   그대로 다리 본문으로 썼는데, 그 정규식은 동사 뒤를 8자만 물어서 결과금리가
   반토막 났다(「팔자+3원  3.267%」 -> 「팔자+3원  3.2」). 그 다리는 문면 금리를 잃고
   «원 환산» 으로 떨어져 값이 달라진다. **매치는 «자를 자리» 로만 쓰고 본문은 자리
   사이를 통째로** 잘라야 한다. `verify_v4 [F2c]` 가 「conv 가 민평에서 35bp 떨어짐」
   으로 그 한 자리를 짚었다 — 오늘 검정이 내 손을 잡은 두 번째 자리다.
16. **★소스에 거래상대 실명·전화번호가 45건 쌓여 있었다.** 화면은 `H09-10` 으로 가리는데
   주석·문서의 예시는 그대로였다. 기계 밖으로 올리기 전에 훑어야 한다
   (`scrub_desk_names.py`). ⚠데스크명을 **전역 치환하면 안 된다** — 「한화」·「삼성」·
   「신한투자증권」은 발행체 이름이기도 하다. 닫힌 «서명 묶음» 안만 가린다.

   300줄 전부가 그렇게 돼 diff 가 570줄로 부풀었다(실제 편집은 48줄).
